技术笔记值得有一个稳定的落脚点。这个网站把文章、项目和个人介绍放在一起，用 Markdown 保存内容，用 Astro 生成静态页面。

## 写作从 Markdown 开始

每篇新文章位于 `src/content/posts/`。文件开头记录标题、摘要、日期和标签，正文专注于问题、思路、实现和验证。文章列表与 RSS 会自动收录公开文章。

一份实用的技术笔记，应该让读者知道：问题在什么场景出现，方案依赖哪些条件，结论由什么证据支撑，还有哪些地方没有验证。

## 先预览，再公开

本地使用 `npm run dev` 预览，完成后运行 `npm run check` 和 `npm run build`。暂时不公开的内容使用 `draft: true`；草稿不会进入公开页面和 RSS。仓库文件本身的可见性仍由 GitHub 仓库设置决定。

## 项目是另一种形式的笔记

项目页集中介绍个人公开实践，并链接到源码仓库。项目说明优先回答目标、实现方式和运行条件；实验代码与生产能力应该分别说明，性能结论需要附带硬件、数据和测试方法。

## 保留原有文章

现有投机解码综述保留原链接与排版。它是一份研究初稿，包含资料核对范围与待复核项；没有经过 GPU 性能对比实验。后续内容可以继续沿着机制理解、工程实现和实验验证三条线更新。
